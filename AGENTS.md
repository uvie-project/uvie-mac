# AGENTS.md — UVieMac

## Build & Test Commands

```bash
UVIE_RS_DIR=../uvie-rs ./build.sh && swift run   # Build + run dev instance
swift test                                        # Run the integration test suite (321 tests)
swift test --filter EngineTypingTests             # Engine typing behavior only
swift test --filter DispatcherTests               # Event-tap dispatch decisions only
swift test --filter FeaturesTests                 # Per-app memory, input-method manager, macros
swift test --enable-code-coverage                 # Coverage: .build/debug/codecov/
xcrun llvm-cov report .build/debug/UVieMacPackageTests.xctest/Contents/MacOS/UVieMacPackageTests \
  -instr-profile=.build/debug/codecov/default.profdata Sources/UVieMac/Core
```

`swift test` requires `Frameworks/libuvie.a` + `Frameworks/Sparkle.framework`
(generated by `build.sh`, or fetched via `scripts/fetch-uvie.sh` +
`scripts/fetch-sparkle.sh`). CI: `.github/workflows/tests.yml` runs
`swift test` on macos-15; `ci.yml` builds the app.

> **Stale engine artifact — check this before blaming the tests.** `Frameworks/*.a`
> is gitignored, so a local copy silently lags the pinned `uvie-rs-version`.
> A cluster of `EngineTypingTests` / `EngineStateTests` / `DispatcherTests`
> failures that all look like *missing* engine features (no `aa`→`â`, no
> post-coda tone resolution, `editAt` returning nil, no mid-word edit) means
> the linked binary is old — the tests are correct. Rebuild with
> `UVIE_RS_DIR=../uvie-rs ./build.sh` (or `scripts/fetch-uvie.sh`) and re-run.
> Sanity check: `Frameworks/libuvie.a` must be newer than the `uvie-rs`
> commit named by `uvie-rs-version` (`git -C ../uvie-rs log -1 --format=%ci`).
> Rebuild manually without touching `Generated/Version.swift`:
> `cargo build --release --target aarch64-apple-darwin` (and `x86_64-apple-darwin`)
> in `../uvie-rs`, then `lipo -create` both `libuvie.a` into `Frameworks/`.

## Release

1. Bump `CFBundleShortVersionString` in `Info.plist` — and *only* that key.
   Leave `CFBundleVersion` alone: CI overwrites it with a Unix timestamp so
   Sparkle always sees a strictly newer build. Commit as
   `chore: bump version to vX.Y.Z`.
2. `git push origin main && git tag vX.Y.Z && git push origin vX.Y.Z`.

`.github/workflows/release.yml` (triggered by the tag) then builds arm64 +
x86_64, lipos, signs, **notarizes**, packages the DMG + the Sparkle zip,
generates the appcast entry, **publishes the GitHub release**, and force-pushes
`appcast.xml` to an orphan `gh-pages` branch that GitHub Pages serves at
`https://uvie-project.github.io/uvie-mac/appcast.xml` (`SUFeedURL`).

- Tag pushes publish immediately. `workflow_dispatch` keeps the `draft` input
  (default true) for a dry run — a draft release would leave the live feed
  advertising a zip that 404s for every user.
- The appcast entry carries **embedded release notes** (`<description>`, built
  from the commit subjects since the previous tag). Do NOT also emit a
  `<sparkle:releaseNotesLink>`: Sparkle prefers the link and would load the
  whole GitHub release page (a heavy SPA) inside the update dialog. With
  neither, the dialog's release-notes pane spins forever ("loading never
  stops, no content") even though the update still installs.
- `gh-pages` is a single-file orphan branch force-pushed each release, so the
  feed only ever holds the newest `<item>`.
- Re-running a failed job is safe (fresh checkout per run). Transient
  `uploads.github.com` connect timeouts have been seen at the asset-upload
  step — just re-run the job.

## Test Architecture

Tests simulate user keystrokes WITHOUT touching the host session:

- **EngineTypingTests** — feed character sequences through the real
  Swift↔Rust engine (EngineBridge FFI) and assert the reconstructed
  on-screen text. Expectations are locked to shipped v2.5.1 behavior
  (tones, w-modifiers, V-C-V, tone cancel, English dictionary override,
  VNI, simple Telex, modern orthography).
- **EngineStateTests** — backspace walk-back, commit, reset,
  introspection, the FFI scratch-buffer reuse contract, editAt decline
  cases, input-method switching, and uppercase raw-key preservation.
- **DispatcherTests** — drive `EventTap.handle()` with synthetic CGEvents
  and assert consume/pass-through decisions plus the injection plan.
  Includes the Cmd+Space → Spotlight refresh-budget regression test, the
  post-commit word-editing flows (arrow-back + tone key, backspace-arms,
  mid-word forward-delete + backspace + full re-render, mouse-down
  disarm), the custom global hotkey
  (in-tap detection: key combos + modifier-only chord taps), the Fn tap
  toggle (Globe key, flagsChanged, debounce, stale-state), English mode,
  non-Latin layout auto-disable, AX-mode routing, excluded-tap state, and
  the per-app sentence-start memory.
- **HelperTests** — key classification tables, selection shortcuts,
  auto-capitalize state machine, macro lookup, `HotkeyBinding` model
  (modifier-only chords, display strings, NSEvent recording), keyboard
  layout Latin/non-Latin classification, and the AX text-composition
  transform (grapheme-cluster drop semantics).
- **FeaturesTests** — per-app language memory (packing, persistence,
  legacy binary migration), InputMethodManager toggle/sync + app-switch
  restore (via a posted NSWorkspace activation notification), macro CRUD +
  persistence, and the Logger trace-cache refresh. UserDefaults keys are
  snapshotted in setUp and restored in tearDown so the user's real
  settings are never polluted.

### Test seams (production code)

Protocols/visibility exist purely so tests can intercept side effects:

- `SyntheticOutputSink` — `EventTap.outputSink` (defaults to `self`);
  tests substitute `RecordingSink` so injections are recorded, not posted.
- `AXTextInjecting` — `EventTap.axInjector`; tests substitute
  `StubAXInjector` (no AX IPC).
- `AppContextDetecting` — `EventTap.appDetector`; tests substitute
  `StubAppDetector` with scripted `refreshBundleID()` results.
- `updateExcludedTapState()` is internal so tests can drive the excluded
  state flip without a real `CGEventTap`.

`makeEventTap()` (Tests/UVieMacTests/TestSupport.swift) pins every
environment-dependent flag (auto-capitalize, macro toggle, app lists,
input method, Fn/custom hotkeys) so tests are deterministic regardless of
the user's real UserDefaults. Tests that trigger a toggle must re-pin the
flag afterwards — the toggle writes to UserDefaults and the resulting
`didChangeNotification` re-runs `applyEngineSettings()`.

### Deliberately untested (system boundaries)

Unit tests must not touch the host session, so these stay uncovered:
`EventTap+SyntheticOutput` (posts real CGEvents), `AXTextInjector`'s AX IPC
(the pure transforms ARE covered: `composeText` and `resolveBase`), `EventTap`
lifecycle (`startTap` creates a real CGEventTap), `GlobalHotkeyManager`
Carbon registration (would register real system hotkeys),
`AccessibilityChecker`/`LaunchAtLoginManager`/`UpdateChecker` (AX trust,
SMAppService, network), and `AppContextDetector`'s AX lookups (covered via
the `AppContextDetecting` stub at every call site).

## Architecture

- `Sources/UVieMac/Core/` — hot path. `EventTap` (CGEventTap callback on
  the main runloop) dispatches to: CGEvent synthetic injection
  (`EventTap+SyntheticOutput`, posts to `.cgSessionEventTap`), AX text
  injection (`AXTextInjector`, used for Spotlight via `axApps`), or
  pass-through. The Vietnamese engine is Rust (`uvie-rs`, linked as
  `libuvie.a`) behind `EngineBridge` — diff API returns
  `(backspaces, suffix)` per keystroke.
- **Spotlight's host process is macOS-version dependent.** `axApps` holds
  both `com.apple.Spotlight` and `com.apple.campo`: on macOS 26 (Tahoe) the
  Spotlight panel belongs to `com.apple.campo` (the Apple Intelligence / Siri
  host) and `com.apple.Spotlight` never appears as the focused application.
  Missing it sent Spotlight through the CGEvent path, where the synthetic
  keycode backspace is ignored while the unicode-string suffix still lands:
  every transform duplicated ("ows" rendered "oớ" / "ớơ"). The
  `dispatch AX key=... app=...` line at info level in `log show` shows which
  path handled a keystroke.
- App classification (excluded/compound/chromium/ax/bypass) is cached in
  `EventTap` and refreshed on settings changes; the focused-app bundleID
  comes from `AppContextDetector` (NSWorkspace notifications) plus a
  budgeted AX refresh (`axRefreshAttempts`, 3 per trigger) for apps that
  never fire activation notifications (Spotlight). The budget is spent in
  ANY app that is not excluded and not already an AX app: compound/chromium
  apps are re-resolved too, because Cmd+Space from Safari/Chrome/Notes/
  TextEdit/Mail is the common way Spotlight opens, and skipping those apps
  left the keystrokes on the CGEvent path Spotlight ignores. When the refresh
  finds a DIFFERENT app it is treated as the app switch the workspace never
  announced: the engine, caret anchor and web-content cache are dropped
  first (otherwise the previous app's composing word is diffed into the new
  one - typing "đó", Cmd+Space, then "w" made Spotlight show "ớ").
  - **Bypass list is user-extendable** (`DefaultsKey.customBypassApps`,
    Settings → Ứng dụng → app menu "Để phím đi thẳng"): system UI + iOS Simulator ship as
    defaults, and users add apps that ignore synthetic CGEvents (VMs,
    Android emulator, remote-desktop clients, raw-input games). `shouldBypass`
    reads `cachedBypassApps`, so the list is hot-path free.
  - **Removing a default app persists** via `DefaultsKey.removedCompoundApps`
    / `removedChromiumApps` / `removedBypassApps`: `getXApps()` computes
    `defaults - removed + custom`. The custom list alone only records
    additions, so writing it without the removed set brought every default
    back on the next launch.
- **Text the engine never saw drops the composition** (`handle`): paste/cut/
  undo (Cmd/Ctrl+V/X/Z) and Option combinations that type a glyph (dead keys,
  e.g. Option+E → ´) insert or remove text behind the engine's back. Keeping
  the composing word alive made the next diff backspace into that text
  ("vie" + paste + "ts" ate two pasted characters). The engine is reset
  before those keys pass through.
- **Language switches reset the engine**: `InputMethodManager.toggle()` /
  `setVietnamese()` (menu bar, popover, Settings master toggle, Carbon
  hotkey) post `.resetEngineForLanguageSwitch`; `EventTap` drops the
  composing word and the caret anchor on it. `triggerToggle()` (Fn tap) does
  the same reset inline.
- **English mode keeps the sentence state machine running**
  (`handleEnglishMode`): auto-capitalize applies there too, and Enter starts
  a new sentence. Without it `isAtSentenceStart` stayed `true` for the whole
  English word, so the first Vietnamese letter typed afterwards was
  capitalized mid-word.
- **Non-ASCII keys are never swallowed** (`handleCharacterKey`): the engine
  only processes ASCII, so an accented/Cyrillic/Greek/combining key used to
  return an empty diff and get consumed — the app looked dead ("events are
  logged but nothing types"). Such keys now commit the composing word, reset
  the engine and **pass through** so the app inserts them natively. A second
  guard after `feed` does the same for any empty-diff/no-composing result
  (mirrors `AXTextInjector.feed`'s "engine didn't process it" check).
- **AX injection never diffs into text it did not write** (`AXTextInjector`):
  the whole field value is rewritten on every keystroke, so the base matters.
  `resolveBase` requires the field to end with the engine's composing output;
  a read that is behind our own last write (`lastWrittenText`) is injected
  from that write (Spotlight's live search updates asynchronously), and any
  other divergence drops the composition and passes the key through. At the
  start of a word the field only counts as ours while it still starts with
  the value we wrote (`lastWrittenText`, cleared on every app switch): any
  other text is the app's, e.g. Spotlight's previous query, and the new word
  replaces it as native typing would. Appending kept that query in front of
  the new word (a leftover "o" plus "ows" rendered "oớ", a leftover "ơ"
  rendered "ơớ"). A fully selected field is replaced too. Backspace also
  drains invisible raw keys here (same `EventTap.maxBackspaceDrain` loop as
  the CGEvent path).
- **Keyboard-layout classification** (`KeyboardLayoutMonitor`) prefers the
  input source's `kTISPropertyInputSourceLanguages` (authoritative) over
  keyword matching on the source ID, and `isLatinSourceID` gained the
  scripts whose IDs carried no keyword (Kazakh, Mongolian, Nepali, Sinhala,
  Tamil, Persian, Pashto, Belarusian, Serbian, Burmese, Khmer, …). A layout
  misclassified as Latin stayed enabled while every key was non-ASCII —
  the trigger for the swallowing bug above. Latin variants of dual-script
  layouts ("Serbian-Latin") are checked first and stay Latin.
- Settings flags read on the hot path are cached in `EventTap` /
  `MacroManager` / `Logger` and refreshed via
  `UserDefaults.didChangeNotification`. External `defaults write` needs an
  app restart; in-app toggles apply immediately.
- Custom toggle hotkey (Settings → "Phím tắt riêng") is detected INSIDE
  the event tap (`EventTap+Hotkey.handleCustomHotkey`), not only via the
  Carbon `RegisterEventHotKey` in `GlobalHotkeyManager`. Carbon only fires
  when the frontmost app reports the key unhandled — MS Word, Zed and other
  apps with custom text engines consume every keyDown, so the registered
  shortcut silently did nothing there. The tap sees the keyDown before any
  app; a consumed event never reaches Carbon's dispatch, so the two
  mechanisms can never double-fire (Carbon remains the fallback while the
  tap is disabled for excluded apps). The binding (keyCode + Carbon
  modifiers → `CGEventFlags` chord) is cached in `EventTap` and refreshed in
  `applyEngineSettings()`; matching compares only the four chord modifiers
  (Cmd/Ctrl/Opt/Shift), ignores padding flags, swallows auto-repeat, and
  consumes both keyDown and keyUp.
- Modifier-only chords (issue #14, e.g. bare ⌘⇧ with no letter key) are
  recorded via the ShortcutRecorder "Xong" (Done) button and stored with
  keyCode `-1` (`HotkeyBinding.modifierOnlyKeyCode`). Carbon cannot register
  them, so they are tap-only: `trackCustomChordTap` fires the toggle when
  the recorded modifiers are TAPPED — pressed and released with no other key
  in between (any real keyDown/keyUp disarms, so app shortcuts like ⌘⇧N keep
  working; release order doesn't matter). The armed state
  (`customChordTapArmed`) resets on app switch, tap disable/timeout, and
  mouse down. Limitation: modifier-only chords don't fire while the tap is
  disabled (excluded apps) — Carbon can't cover them.

## Post-commit word editing (LabanKey-style)

Type a word, commit it (space/Enter), press **Left arrow** to step the caret
back onto the word end — or INTO the word — then type a tone/modifier key —
the committed word is re-rendered in place (`don` + space + ← + `s` → `dón`,
or caret `do|n` + `s` → `dón`). Mid-sentence editing works too: arrow back
onto ANY of the last 8 committed words (each word-end boundary is one arrow
step past the newer words' ends) and type. Implemented by:

- **Engine ring** (`uvie-rs`): `commit_diff()` records
  `(raw, rendered, gap)` per committed word (`gap` = separator chars after
  it, reported by the host with `uvie_engine_note_separator` /
  `uvie_engine_remove_separator`; an idle commit records nothing).
  `uvie_engine_edit_at(caret_back, ch)` walks the ring from the newest
  backward accumulating `rendered_len + gap` per older word, and fires when `caret_back` EXACTLY
  matches a word-end boundary (0 = newest word) or lands strictly inside
  a word (mid-word edit). The host's tracked offset
  is the ground truth: any model drift (double spaces, pastes, unseen jumps)
  declines safely — never a wrong-span deletion.
- **Mid-word edits** (`forwardDeletes > 0`): the engine rewrites the whole
  word — backspaces cover the rendered chars left of the caret,
  `forwardDeletes` covers the old word's tail right of the caret, and the
  posted suffix is the full re-rendered word. The host removes the tail
  FIRST (`applyCompoundForwardDeletes` — Shift+Right selection + one
  Forward Delete in native fields, plain forward-deletes in Chromium web
  content where synthetic selection doesn't take), then the left part
  through the normal compound-aware path, then posts the word. The caret
  lands at the edited word's end.
- **In-place edits**: the edited entry is updated in place, every other
  word stays editable, and the engine stays idle. The host re-anchors with
  `EngineBridge.lastCaretBack` (the edited word's end).
- **Backspace re-open**: Backspace at a committed word's end
  (`editCaretBack == end(k)`) calls `backspaceAt(caretBack:)`, which undoes
  that word's last keystroke in place ("viêt " ⌫⌫ + `j` → "việ").
- **`EventTap.editCaretBack`** — caret offset (screen chars) from the end of
  the newest committed word (the "anchor"). `0` = caret at the anchor
  (edit-armed); negative = right of it (normal post-commit position);
  positive = caret moved into earlier text.
  - Plain Left/Right arrows are intercepted BEFORE the modifier-cursor
    reset (real hardware arrow events carry `.maskSecondaryFn` +
    `.maskNumericPad` with no modifier held): commit the composing word
    first, then step (`editCaretBack ± 1`). Cmd/Ctrl/Option+arrows and
    Shift+arrows still reset. Other cursor keys, Tab, mouse, selection
    shortcuts, modifier-cursor, Escape, Option+Backspace, non-Latin layout,
    app switch: full reset + `editCaretBack = 0`.
  - Backspace while idle: `editCaretBack >= 0` → `backspaceAt` (declines
    mid-word → OS delete + reset); `< 0` → a separator was deleted →
    `removeSeparator()` + offset +1 (deleting the space arms editing), or a
    reset when no separator is tracked there.
  - Character key while armed (`editCaretBack >= 0`, engine idle) →
    `EngineBridge.editAt(caretBack:char:)` → inject the diff through the
    normal compound-aware path and re-anchor to `lastCaretBack`. Off-boundary
    decline → reset + normal feed; `< 0` feeds a fresh word only at the end
    of the trailing separators (`-trailingGap`), otherwise resets first.
  - Space/Enter/punctuation (`afterWordBreak`): composing → commit, note
    the separator, `editCaretBack = -1`; idle at the end of the tracked
    separators → note another one; anywhere else → reset. Punctuation is
    committed and PASSED through (never fed — feeding it used to wipe the
    ring).
  - Control-gap guard (`trailingGapHasControl`): a control separator
    (Enter, Break) may have been sent or cleared rather than inserted —
    a chat app's newline is unconfirmed geometry. Backspace (both paths),
    Forward Delete inside the gap, and Left while `editCaretBack < 0` reset
    and pass the key natively instead of touching the gap; Right still
    steps (it only moves within/past the tracked gap).
  - Separator deletes: at the END of the gap (`editCaretBack ==
    -trailingGap`) `removeLastSeparator()` undoes exactly the state the
    separator created (comma stays known, retro restore works); inside the
    gap `removeSeparator()` goes conservative and marks the surviving
    separator unknown.
- Gated by `DefaultsKey.editCommittedWords` (default ON, cached in
  `editCommittedEnabled`, refreshed on settings changes; Settings → Gõ phím
  → "Sửa lại từ đã gõ"). Disabled for AX apps (Spotlight) — AX injection
  rewrites the whole field.
- Known limits: untracked text (pastes, mouse moves) declines safely or
  resets; mouse/selection/Tab resets recover. Mid-word edits can't restore
  the caret to its original position — after an edit it sits at the word's
  end.

## Input Source mode (experimental, v3.0.0, flag OFF by default)

An optional second input path: a real macOS input method (InputMethodKit)
that renders the composing word through the text-input protocol instead of
synthetic backspaces. Chromium pays for every synthetic edit in proportion to
the field's text length, and a tone key is 5-6 edits on the event-tap path;
the input method needs one. `DefaultsKey.inputSourceModeEnabled` gates it
(Settings -> Hệ thống -> "Bộ gõ hệ thống"); with the flag off nothing is
installed and the event tap behaves exactly as in v2.

- **One binary, two bundles.** `Sources/UVieMac/App/main.swift` picks the
  role from the bundle identifier: `com.uvie-project.inputmethod.UVie` runs
  `InputSourceRuntime.runServer()` (IMKServer only - no AppDelegate, event
  tap, menu bar or Sparkle), anything else runs `UVieMacApp.main()`.
  `scripts/build-im-bundle.sh` assembles `UVieIM.app` (same binary,
  `InputMethod/Info.plist`); release.yml nests it in
  `UVieMac.app/Contents/Helpers` and signs it before the outer app. Sparkle
  is weak-linked because the IM bundle carries no Sparkle.framework.
- **Mutual exclusion.** `KeyboardLayoutMonitor.isUVieInputSourceActive` is
  true while the UVie input method is the selected input source;
  `EventTap.inputSourceActive` caches it and `handle()` passes every keyboard
  event through after the language-toggle hotkey block. Switching to any
  other input source re-arms the tap. Our own source never counts as a
  non-Latin layout.
- **Centralized settings.** The IM process adds the app's defaults domain
  (`UserDefaults.standard.addSuite`) so shared code reads the app's values;
  `SharedSettingsBroadcaster` (app process, only while the flag is on) posts
  a distributed notification on every defaults / language change and the IM
  reloads. The Vietnamese/English flag and the per-app memory stay owned by
  the app process (`InputMethodManager` + `MemoryManager`).
- **Rendering** (`InputSourceComposer`, unit-tested against a fake text
  field): `marked` style shows the word as marked text and commits it on a
  boundary; `direct` style replaces the word's UTF-16 tail in place and
  falls back to marked text per app as soon as the client's selection does
  not match the expected caret (asynchronous clients, ignored replacement
  ranges) - it never replaces text on a failed precondition.
- **Not in this mode yet:** auto-capitalize, post-commit word editing, and
  cross-word retro rewrites in marked style (the word is committed as shown).
- **Not yet verified on a real machine:** key delivery through IMK in real
  apps, and `TISEnableInputSource` (in one attempt on a locked session it
  returned noErr but the source stayed disabled, so `TISSelectInputSource`
  failed with -50; the user may have to add "UVie" under System Settings ->
  Keyboard -> Input Sources by hand).
- **A flush is not a word boundary** (`InputSourceComposer.flush`): language
  off, a settings change, Cmd/Ctrl/Option chords, arrows and focus loss
  finalize the word exactly as shown and reset the engine - they never run
  the commit rules, which would restore an incomplete syllable's raw keys
  ("việ" must not turn back into "vieej"). Only space, punctuation and
  Return commit through `commitWith`.
- **Marked style cannot rewrite earlier words**: when a commit's diff
  reaches past the composing word (the retroactive English restore, "this is
  the best ..."), the word is committed as shown and the engine history is
  dropped. Direct style applies the rewrite with a replacement range.
- `InputSourceModeController` reports `.active` only when the source is
  really selected afterwards (`enableAndSelect` returns `isSelected`); after
  the retries it shows the "add UVie in System Settings" guidance and keeps
  the flag on.
- **Tests are independent of the session state**: `makeEventTap()` pins a
  `StubAppDetector` and the `isSecureEventInputEnabled` seam, so the suite
  passes on a locked screen (frontmost app `loginwindow`, secure input on).
  `InputSourceEquivalenceTests` asserts that the input-source path and the
  event-tap path render the same text for a Telex/VNI/mixed corpus and for
  every backspace step.

## Escape restores English (EVKey-style)

Escape while the engine is composing restores the raw keystrokes of the
current word: the rendered form is erased (compound-aware backspaces)
and the literal raw chars are posted — `"viêt"` + Esc → `"vieet"`.
`rawChars()` (`uvie_engine_raw_chars`) returns the WHOLE word's
keystrokes, not just the composing syllable: `"master"` renders `"mátẻ"`
(V-C-V split committed `"má"`, only `"ter"` composes) and Esc restores
`"master"` — posting the composing tail alone produced `"ter"`.
Consumed only when `rawChars() != currentOutput()`; when the render
already equals the raw input, or the engine is idle, Escape passes
through normally so the app still receives it. An EMPTY `rawChars()` means
the word outgrew the engine's 24-keystroke raw buffer (its prefix was
committed mid-word): restoring would delete text the raw no longer
covers, so Escape cancels instead.

## Notes

- Synthetic events are tagged with `eventSourceStateID = 0x55564945`
  ("UVIE") so the tap skips its own output.
- `warmUpSyntheticKeycodePath()` posts sacrificial events at tap creation:
  the first keycode post from a freshly-rebuilt binary can be dropped.
- AX injection trusts the `AXError` from the set call — never verify with a
  read-back (races Spotlight's live search → double input).
